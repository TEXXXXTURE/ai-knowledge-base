# CONTRIBUTING — 贡献指南

欢迎！这是一个开源的 AI 知识库——**「一线知识的沉淀与导航站」**。用大白话讲清楚 AI 圈子里每天冒出来的新词，让所有人都能看懂。

## 双层结构

知识库分两层，别放错位置：

- **概念库（沉淀层）** `docs/词条/` —— 稳定、可信的词条页。[稳定] 已沉淀 / [热词] 社区热词，互相链接，点击跳转。
- **前沿采集（未沉淀区）** `采集/` —— 机器自动扫描出的新词、新动向，只做记录，不做承诺。这里的内容未经审校。

## 四层贡献模型

谁都能参与，但分工不同。**「可以写」不等于「能发」**——任何人能提交，但只有过校验 + 审校才能发布。

```
L1 读者：纠错 / 补充 / 讨论 → GitHub Issue（不能改，但能说）
L2 社区贡献者：提交词条草稿 → Pull Request（可以写，不能发）
L3 核心维护者（维护者 + 审校 Agent）：合并 / 改稿 / 定稿
L4 机器（采集 Agent）：自动抓热词卡 → 只能进「采集/」目录（未沉淀区）
```

### L1 读者：说，就行
发现错误、过时信息、看不懂的地方，开 GitHub Issue：
- 标题写清楚词条名，正文写明：哪里有问题、你认为应该是什么、（最好附上）来源链接。
- 讨论概念本身也欢迎，争议观点可能被收录进词条的「争议 / 讨论」区。

### L2 社区贡献者：写词条，发 PR
- 按下面的「新词条提交流程」提交词条草稿。
- 你的草稿会自动过 Schema 校验（CI）：字段缺失、无来源、格式不对 → 自动打回，改完再推。
- AI 辅助写作完全 OK，但关键论断必须有人工核对过的来源。

### L3 核心维护者：定稿与发布
- 审校读感、判断、取舍；有权改稿、合并或打回。见 MAINTENANCE.md。

### L4 机器：只进采集区
- 采集 Agent 自动扫描生成的热词卡只写入 `采集/`，不会直接变成正式词条。热词升级为词条走 L2/L3 流程。

## 新词条提交流程

1. **Fork** 本仓库。
2. **建分支**：`add-术语名`（如 `add-LoRA`）。
3. **写词条**：在 `docs/词条/` 下新建 `术语名.md`，用下面的模板，按 CONTENT-SPEC.md 的规范写。
4. **提交 PR**：标题写「新词条：术语名」，正文简要说明来源和价值。
5. **过校验**：CI 自动跑 Schema 校验，红了就按报错改（对照 CONTENT-SPEC.md 第四节的检查清单）。
6. **等审校**：维护者人工审校，可能提出修改意见，也可能直接改稿。
7. **合并**：通过后合并，站点自动重建，词条上线。

改已有词条同样走 PR，分支名用 `fix-术语名` 或 `update-术语名`。

## 词条模板（直接复制）

保存为 `docs/词条/术语名.md`（文件名 = 术语名，避免特殊字符）：

```markdown
---
term: LoRA                  # 术语名（英文原名）
full_name: Low-Rank Adaptation   # 全称
aliases: [低秩适配]              # 别名
category: 模型微调               # 分类（从 CONTENT-SPEC.md 第五节选择）
maturity: hot                   # stable / hot，新词条默认 hot
status: draft                   # draft / review / published
contributors: [你的GitHub用户名]
sources:                        # 至少 1 条，无源不收录
  - https://arxiv.org/abs/2106.09685
related: [微调, PEFT]            # 关联概念
created: 2026-08-14
updated: 2026-08-14
revisions: 1
---

> [热词] 社区热词，未经沉淀，信息可能快速过时。（maturity 为 hot 时保留这行，stable 时删掉）

## 定义
一段话讲清楚这是什么。人话优先，先打比方再给严谨说法。

## 详解
2-5 段。深入但可读，术语首次出现带英文全称。

## 为什么重要
对学习者/使用者来说，这个词为什么值得知道。

## 争议 / 讨论（如有）
社区的正反观点 + 各自来源。没有就整节删掉。

## 参见
- [微调](微调.md)
- [PEFT](PEFT.md)
```

## 行为准则

- 友善协作，对事不对人。争论观点可以，攻击人不行。
- 尊重来源，不抄不编。AI 生成内容必须经过人工核对。
- 写的东西面向所有读者：如果你是领域专家，请降维讲；如果你是新手，看不懂就提 Issue，这本身就是贡献。
